设计文档

版本: 2.0 | 日期: 2026年5月31日 | 状态: 已完成（存储层重构：localStorage → 本地文件系统 + Node.js 数据服务）

1. 系统架构

1.1 整体架构

本应用采用前端页面 + 本地数据服务的两层架构：

前端层（index.html）

  • HTML 结构：定义页面布局和 DOM 元素
  • CSS 样式：提供浅色主题和响应式设计
  • JavaScript 逻辑：实现所有业务功能，通过 HTTP API 与数据服务通信

数据服务层（server.js）

  • 静态文件服务：提供 index.html 的 HTTP 访问
  • 数据读写 API：GET /api/data（读取）、POST /api/data（写入）
  • 文件持久化：将数据写入 D:\重要数据\info_data.json
  • 端口自动回退：从 3456 开始，被占用时自动尝试下一个端口（最多到 3465）

数据流

浏览器（http://localhost:3456）
    ↕  fetch API（GET/POST /api/data）
Node.js 数据服务（server.js）
    ↕  fs.readFileSync / fs.writeFileSync
D:\重要数据\info_data.json

这种设计的优点是数据持久化不受浏览器缓存影响、数据存储容量大、可跨浏览器共享数据。

3. 核心模块设计

3.1 数据管理模块

职责：管理数据的增删改查和持久化

关键函数：
  • save() - 通过 HTTP API 将数据保存到本地 JSON 文件
  • saveEntry() - 保存单条记录
  • deleteEntry(id) - 删除单条记录
  • editEntry(id) - 编辑记录
数据结构： 
entries = [
  {
    id: "1234567890",
    name: "GitHub",
    url: "https://github.com",
    user: "username",
    pass: "password",
    note: "个人账号",
    createdAt: "2026-05-27T10:30:00.000Z"
  },
  ...
]

3.2 UI 渲染模块

职责：根据数据状态渲染页面

关键函数：
  • render() - 主渲染函数，更新整个列表
  • getFiltered() - 获取过滤后的数据
  • updateStats() - 更新统计信息
  • updateBatchBar() - 更新批量操作栏
渲染流程： 
用户操作 → 修改 entries 数据 → await save() → 调用 render() → 更新 DOM

3.3 表单管理模块

职责：管理信息录入和编辑表单

关键函数：
  • showForm(name, url) - 显示表单（新增或编辑）
  • hideForm() - 隐藏表单
  • clearForm() - 清空表单
  • saveEntry() - 保存表单数据
表单字段：
  • fName - 网站名称
  • fUrl - 网站地址
  • fUser - 账号
  • fPass - 密码
  • fNote - 备注

3.4 搜索过滤模块

职责：实现搜索和时间过滤功能

关键函数：
  • getFiltered() - 根据搜索词和时间范围过滤数据
过滤逻辑： 
1. 获取搜索关键词（searchInput）
2. 获取时间范围（groupSelect）
3. 遍历 entries，匹配搜索词
4. 根据时间范围进一步过滤
5. 返回过滤结果
时间范围：
  • all - 全部
  • today - 今天
  • week - 本周（7天内）
  • month - 本月

3.5 批量操作模块

职责：实现批量选择、导出、删除功能

关键函数：
  • toggleSelect(id) - 切换单条记录的选择状态
  • toggleAll() - 全选/反选
  • batchExport() - 批量导出选中记录
  • batchDelete() - 批量删除选中记录
数据结构： 
selected = new Set()  // 存储已选择的记录 ID

3.6 导入导出模块

职责：实现数据的备份和恢复

关键函数：
  • exportData() - 导出全部数据为 JSON
  • batchExport() - 导出选中数据为 JSON
  • importData(event) - 导入 JSON 文件
导出格式： 
[
  { id, name, url, user, pass, note, createdAt },
  ...
]
导入逻辑：
  • 验证文件格式是否为有效 JSON 数组
  • 检查每条记录的 ID，避免重复导入
  • 为缺少 createdAt 的记录添加当前时间
  • 将新记录添加到列表顶部

3.7 数据服务模块

职责：提供 HTTP API 接口，管理本地 JSON 文件的读写

服务端文件：server.js（Node.js，仅使用内置模块 http / fs / path）

API 接口：
  • GET /api/data - 读取 D:\重要数据\info_data.json 并返回 JSON 数组
  • POST /api/data - 将请求体中的 JSON 数组写入 D:\重要数据\info_data.json
前端调用：
  • loadData() - 页面启动时调用 GET /api/data 加载数据
  • save() - 数据变更后调用 POST /api/data 持久化（async/await）
关键特性：
  • 进程标识：process.title = 'info-library-server'，便于在任务管理器识别
  • 端口自动回退：从 3456 起尝试，被占用则递增（最多 3456~3465）
  • 请求体大小限制：10MB
  • 服务启动后自动打开浏览器
  • 数据目录和文件自动创建（如果不存在）

3.8 书签工具模块

职责：生成和管理书签工具

关键函数：
  • setupBookmarklet() - 生成书签代码
  • checkAutoFill() - 检查 URL 参数并自动填充表单
工作流程： 
1. setupBookmarklet() 生成 JavaScript 书签代码
2. 用户将书签拖到浏览器书签栏
3. 用户在任意网页点击书签
4. 书签执行 JavaScript，打开本应用并传递 URL 参数
5. checkAutoFill() 读取参数，自动填充表单
6. 用户填写账号密码后保存
书签代码（使用剪贴板 API，兼容 HTTP 环境）： 
javascript:void(navigator.clipboard.writeText(
  JSON.stringify({infoLib:true,name:document.title,url:location.href})
))

3.9 统计分析模块

职责：计算和显示统计信息

关键函数：
  • updateStats() - 更新统计数据
统计指标：
  • 总记录数 - entries.length
  • 今日新增 - createdAt 为今天的记录数
  • 本周新增 - createdAt 在过去7天的记录数
  • 本月新增 - createdAt 在本月的记录数
  • 高频关键字 - 从 name 和 note 中提取，排序后取前3个
关键字提取逻辑： 
1. 将 name 和 note 合并
2. 按空格和标点符号分割
3. 过滤掉长度 < 2 的单词
4. 过滤掉纯数字
5. 过滤掉协议关键字（http, https）
6. 统计每个单词出现次数
7. 按频率排序，取前3个

6. 安全性设计

6.1 数据安全

  • 本地存储：所有数据存储在本地 JSON 文件（D:\重要数据\info_data.json），不上传到外部服务器
  • 密码隐藏：密码默认显示为点号，用户可选择显示
  • HTML 转义：使用 esc() 函数转义用户输入，防止 XSS 攻击

6.2 用户提示

  • 在页面顶部显示数据文件路径，提醒用户不要手动修改文件
  • 建议用户定期导出备份
  • 删除操作前要求确认

7. 性能优化

  • 单文件设计：无需加载外部资源，加载速度快
  • 事件委托：使用事件委托而非为每个元素绑定事件，减少内存占用
  • DOM 批量更新：使用 innerHTML 一次性更新列表，而非逐个添加元素
  • 搜索防抖：搜索输入时实时过滤，无需额外的防抖处理

9. 扩展性考虑

  • 模块化：各功能模块相对独立，易于添加新功能
  • 数据结构：记录结构灵活，可添加新字段而不影响现有功能
  • 事件系统：使用事件委托，新增的 DOM 元素自动支持事件处理
  • 未来扩展：可考虑添加分类、标签、搜索历史等功能
